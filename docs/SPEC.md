# Christopher Nolan — Build Spec (v0.1)

Agent-driven, agent-agnostic video studio on top of Remotion. Any coding agent (Claude Code, Codex, Cursor, Gemini CLI, OpenCode, Copilot) drives it through one skill (`skills/nolan/SKILL.md`) and one Node CLI (`node cli/nolan.ts`). Base usage needs **no API key**: the host LLM does the thinking, free sources (Openverse, ccMixter, `@remotion/sfx`, bundled pack) give audio. `OPENROUTER_API_KEY` optionally unlocks voice-over (TTS), AI images, second-model scenario critique and experimental AI music, all behind a **hard USD budget**.

Research briefs with verified facts live in `docs/research/*.md` — **read the ones relevant to your task before coding**. `critic.md` corrects the others and wins on conflict.

Code/docs language: English. The agent talks to the user in the user's language.

## 0. Hard constraints
- Node >= 22.18 (native TypeScript type-stripping). CLI is plain `.ts` run with `node cli/nolan.ts` — **erasable syntax only**: no `enum`, no `namespace`, no parameter properties; use `import type` for types; imports must include the `.ts` extension. No `tsx`, no build step for the CLI.
- Pin every `remotion`/`@remotion/*` package to exactly `4.0.530` (no `^`). `zod@4.5.4`, `react@19.2.3`, `react-dom@19.2.3`, `typescript@5.9.3`, `@types/react@19.2.7`, `shiki@4.4.3` for code highlighting (not Code Hike).
- Ponytail: stdlib first, no new deps unless listed here. Fewest files. No abstractions for one caller.
- ffmpeg: prefer system `ffmpeg`/`ffprobe` on PATH, else `npx remotion ffmpeg`/`ffprobe` (no `afade`, no `ebur128`, no lavfi there — see critic.md). Fades/ducking are done in Remotion, not ffmpeg.
- Everything must work on Linux, macOS, Windows paths (use `node:path`, forward slashes for staticFile paths).
- Pass `--props` to Remotion as a **file path**, never inline JSON.

## 2. Scenario schema (`src/schema.ts`, zod v4, used by BOTH Remotion and CLI)
Flat and Studio-friendly (no discriminated unions; `type` enum + optional fields). Export `ScenarioSchema`, `SceneSchema`, types `Scenario`, `Scene`, and constants `SCENE_TYPES`, `THEME_PRESETS`, `TRANSITIONS`, `FORMATS`. Use `zColor()` from `@remotion/zod-types` for colors, `zTextarea()` for long text.
```
Scenario {
  slug: string; title: string;
  format: "16:9" | "9:16" | "1:1"            // 1920x1080 | 1080x1920 | 1080x1080
  fps: number (default 30)
  theme: { preset: THEME_PRESETS; accent?: color; background?: color; text?: color;
           displayFont?: string; bodyFont?: string; monoFont?: string; grain?: 0..1; energy?: "calm"|"medium"|"punchy" }
  transition: { type: TRANSITIONS; frames: number }        // default between scenes
  audio: {
    music: { enabled: boolean; src?: string (path under public/); volume: 0..1 (0.5); duckTo: 0..1 (0.2); mood: string[]; bpm?: [lo,hi] }
    sfx:   { enabled: boolean; auto: boolean; volume: 0..1 }
    voice: { enabled: boolean; volume: 0..1 }
  }
  scenes: Scene[]
}
Scene {
  id: string; type: SCENE_TYPES; seconds: number; transition?: TRANSITIONS (overrides default for the cut AFTER this scene)
  narration?: textarea           // voice-over text (TTS) or on-screen caption source
  voiceSrc?: string              // set by `nolan ai tts`
  background?: string            // optional image path under public/
  sfx?: { name: string; at: number (seconds within scene); volume?: number }[]
  // type-specific (all optional):
  title?, subtitle?, text?, bullets?: string[],
  code?: textarea, lang?: string, filename?: string, highlight?: string ("3-5,8"), typing?: boolean (default on; false shows the code at once),
  tree?: string[] (paths), focus?: string (path to highlight),
  nodes?: { id; label; col; row }[], edges?: { from; to; label? }[],
  commands?: { cmd: string; output?: string }[],
  stats?: { label; value: number; prefix?; suffix? }[],
  quote?, author?, image?: string, before?: string, after?: string, cta?: string, url?: string
}
SCENE_TYPES = title | kinetic | code | tree | diagram | terminal | stats | bullets | quote | image | compare | outro
THEME_PRESETS = interstellar (default) | neon-terminal | editorial-light | brutalist | retro-crt | clean-dark
TRANSITIONS = fade | slide | wipe | flip | none | dreamyZoom | filmBurn | blurSlide   (verify each exists in @remotion/transitions 4.0.530; drop those that don't)
```
Also export `sceneFrames(scene, fps)` and `totalFrames(scenario)` (accounts for TransitionSeries overlap) in `src/lib/timing.ts`, importable by the CLI (pure TS, erasable syntax).

## 3. Remotion side (`src/`)
- `index.ts` → `registerRoot(RemotionRoot)`.
- `Root.tsx` is GENERATED by `nolan studio`: one `<Composition id={slug-as-valid-id} component={Video} schema={ScenarioSchema} calculateMetadata={calculateMetadata} defaultProps={ /*inline object literal*/ } />` per project listed. Inline literal is mandatory for Studio's 💾 save. Marker comments `// nolan:begin <slug>` / `// nolan:end <slug>` around each composition so `sync` can find it. Width/height/fps/duration come from calculateMetadata (from `format`, `fps`, `totalFrames`).
- `calculate-metadata.ts`: computes dimensions/duration; highlights code scenes with shiki `codeToTokens` (theme from preset) into an optional derived prop `_tokens` (declare as optional in schema, strip it in `sync`); fetches `staticFile('projects/<slug>/assets.lock.json')` (tolerate 404) into optional derived prop `_credits` for the outro.
- `Video.tsx`: ThemeProvider (preset + overrides + google fonts via `@remotion/google-fonts`), `TransitionSeries` of scenes, grain/vignette overlay, `<Mix>`.
- `scenes/*.tsx`: the 12 scene types per `docs/research/design.md` §2 (premium motion, springs from theme, safe margins, 9:16 aware via `useVideoConfig`). Outro renders CTA + scrolling credits from `_credits` (music/sfx/images attribution — REQUIRED for CC-BY).
- `audio/Mix.tsx` using `Audio` from `@remotion/media`: music bed (loop, fade-in 1s/fade-out 2s, duck to `duckTo` under voice ranges with 8-frame ramps), per-scene voice, explicit scene sfx, and when `audio.sfx.auto`: whoosh 5 frames before each cut, impact on title/outro start, riser ending on the first scene after `title` if present, click bursts (max 1 per 3 frames) during code/terminal typing, ding on stats landing. SFX resolved by name from `public/sfx/<name>.(wav|mp3)` — use a generated manifest `public/sfx/index.json` (name → file) to avoid 404 guessing.
- Studio caveat (document it): only Props-panel edits persist for data-driven scenes; timeline drag edits need an "ejected" scene (out of scope v1, mention in docs).

## 4. CLI (`node cli/nolan.ts <cmd>`; also `npm run nolan -- <cmd>`)
Output is concise, agent-readable; every command ends with a `next:` line suggesting the next command. `--json` flag where useful (status, audio search, scan). Exit code != 0 on failure with a one-line cause + fix.

Project stages (projects/<slug>/state.json: `{slug, stage, createdAt, updatedAt, repo?, version, approved?: {version, file, at}, history: [{at, stage, note}]}`):
`brief → scan → grill → inspiration → scenario → assets → preview → approved`
(`scan` skipped when no repo; `inspiration` skippable.) Resume = `nolan status <slug>` prints the stage and exactly what to do next.

Commands:
| cmd | does |
|---|---|
| `doctor` | node version, deps installed, ffmpeg source, Chrome headless (remotion browser), Openverse reachability, OpenRouter key + budget remaining |
| `setup` | vendor `@remotion/sfx` allowlist (whoosh, whip, mouseClick→click, uiSwitch→switch, ding, pageTurn→page-turn, shutterModern→shutter) into public/sfx as wav + write public/sfx/index.json; `npx remotion browser ensure`; create config dir |
| `new <slug> [--title T] [--repo PATH] [--format 16:9|9:16|1:1]` | create projects/<slug>/ with state.json, brief.md template, starter scenario.json (valid, 3 scenes) |
| `list` / `status [slug] [--json]` | projects + stage + next action |
| `stage <slug> <stage> [--note]` | set stage (validated order-free) |
| `scan <slug> [PATH]` | repo facts → repo-facts.json: name, description (package.json/README first paragraph), languages by extension with LOC, top-level tree (git ls-files, max 200 entries), key files (entrypoints, configs), dependencies, git stats (commit count, contributors, first/last commit dates, recent 10 commit subjects), 3–5 interesting code excerpts candidates (short functions, <= 25 lines) |
| `validate <slug>` | zod-validate scenario.json, print per-scene timing, total duration, warnings (missing assets, text too long for reading time `max(1.5s, words/3.5)`, >4 bullets, code > 18 lines) |
| `audio search --kind music\|sfx --q "..." [--length short] [--json]` | Openverse search (safe licenses `cc0,pdm,by`; `--allow-sa` adds by-sa), scored & listed |
| `audio music <slug> [--q ...] [--pick N]` | auto: query from scenario.audio.music.mood; Openverse → ccMixter → bundled; download, trim to video length+2s if longer, loudnorm -16 LUFS, mp3 48k → public/projects/<slug>/audio/music.mp3; set scenario.audio.music.src; append assets.lock.json |
| `audio sfx <slug>` | for each sfx name referenced (auto cues + scene sfx) missing from public/sfx: fetch from Openverse freesound (length=shortest), normalize, store public/projects/<slug>/audio/sfx-<name>.mp3, lock entry |
| `audio all <slug>` | music + sfx |
| `studio <slug> [--port 3123]` | regenerate src/Root.tsx for this slug (+ any other project with state preview or later? no: only this slug + keep it simple), start `npx remotion studio` detached (write pid to projects/<slug>/.studio.pid), print URL. `--stop` kills it |
| `sync <slug>` | read the inline defaultProps literal between markers in src/Root.tsx (evaluate with `new Function('return (' + literal + ')')` — local trusted file), strip derived `_*` props, zod-validate, if different from scenario.json → snapshot old, write new, print diff summary |
| `snapshot <slug> [--note]` / `versions <slug>` / `restore <slug> <vNNN>` | versions/vNNN.json with note; restore snapshots current first |
| `render <slug> [--draft] [--out FILE]` | sync (if Root has slug), validate, snapshot, `npx remotion render src/index.ts <compId> projects/<slug>/renders/<slug>-vNNN.mp4 --props=projects/<slug>/scenario.json` (draft: `--scale=0.5 --crf=28`), plus thumbnail still; print path + size + duration |
| `stills <slug> [--every 3] [--frames a,b,c]` | render PNG frames to projects/<slug>/stills/ for agent visual QA (agent reads the images) — default: one frame per scene, at the middle or once typing/terminal/stat animations have finished |
| `approve <slug>` | require a non-draft render of current version; set stage approved with file; `reopen <slug>` sets stage back to scenario |
| `config get\|set <key> <value>` / `config set-key` | ~/.config/christopher-nolan/config.json (budgetUsd default 2.00, grillMode sequential\|rounds default sequential, defaultTheme, studioPort 3123) and `.env` for OPENROUTER_API_KEY (read from stdin, chmod 600) |
| `ai status` | key present?, budget cap, spent, remaining, `GET /api/v1/key` limit_remaining cross-check |
| `ai tts <slug> [--voice V] [--model M]` | per scene with narration: `/api/v1/audio/speech` mp3 → public/projects/<slug>/voice/<id>.mp3, probe duration, set voiceSrc, extend scene.seconds to voice+0.6s if shorter |
| `ai image <slug> <sceneId> --prompt "..." [--model M]` | `/api/v1/images` → public/projects/<slug>/images/<sceneId>.png, set scene.image (image scene) or scene.background |
| `ai critique <slug> [--model M]` | chat completions with brief + repo-facts + scenario → critique.md (structured: strengths, issues, concrete edits as JSON patch-like list). Agent decides what to apply with the user. |
| `ai music <slug>` | EXPERIMENTAL Lyria clip via chat completions audio modality; guarded, clear error if response shape differs |

OpenRouter budget (cli/ai/ledger.ts): ledger at `~/.config/christopher-nolan/ledger.jsonl`. Reserve estimate before each call (refuse if `spent + estimate > budgetUsd`, message tells how to raise: `config set budgetUsd 5`), settle with actual `usage.cost` / `/generation?id=` (retry 1,2,4,8s; keep estimate if unknown), void on failure. 402 → hard stop. Default models (overridable via config): tts `google/gemini-3.8-flash-lite-tts` (voice from `supported_voices`, French: prefer a voice that supports fr), image `recraft/recraft-v4.1-flash`, critique `openai/gpt-5.6-luna`. Model IDs are volatile: on 404/400 "model not found", fetch the models list and print candidates.

Audio details: see docs/research/audio.md + critic.md. Cache Openverse responses in `.cache/openverse/`. Send a descriptive User-Agent. Reject ND/NC always. `assets.lock.json` entries: `{id, kind: music|sfx|voice|image, file, title, creator, license, licenseUrl, attribution, sourceUrl, provider}` — the outro credits come from it; CREDITS also printed by `render`.

## 5. Skill (`skills/nolan/SKILL.md`, < 300 lines) — the agent's playbook
Frontmatter: `name: nolan`, description with triggers (video, presentation video, demo video, Remotion, trailer, "make a video of my repo"), `license: MIT`, `compatibility: Node 22.18+, git, Chrome (auto-installed by Remotion). Optional: ffmpeg, OPENROUTER_API_KEY`.
Flow (each step updates state via CLI; the agent must always start with `nolan status`):
1. **Locate/bootstrap workspace**, `doctor`.
2. **Brief**: ask the base idea (one question at a time), then whether an existing repo is the subject (path or URL; clone URLs into a temp dir). `new`, write brief.md.
3. **Scan** (if repo): `scan`, then the agent reads repo-facts.json and key files itself to understand the code (facts are never asked to the user).
4. **Grill** the scenario: if a `grilling` skill (mattpocock) is available use it on the video design tree, else follow `references/grill.md` (embedded adaptation, MIT notice). Default one question at a time (config grillMode), each with a ➡️ recommended answer. Log decisions in grill.md. Ends only when the user confirms the shared understanding.
5. **Inspiration**: use the host's web search (if any) per `references/inspiration.md` → inspiration.json (refs, preset + ≤3 overrides, music moods/bpm). Show the user a 3-line summary; skip gracefully without web tools.
6. **Scenario**: write scenario.json (per `references/scenario.md`, structures from design brief), `validate`. Optional `ai critique` if key.
7. **Assets**: `audio all`; optional `ai tts` / `ai image` (announce cost estimate first).
8. **Preview**: `studio`, give the URL, explain what can be edited in the Props panel + 💾; `stills` and look at them yourself to catch visual bugs before the user does. Iterate: user edits in Studio → `sync`; user asks changes in chat → edit scenario.json (Studio hot-reloads after `studio` regenerates Root — run `studio` again or edit Root via regeneration).
9. **Validate**: `render` (full quality), show path, ask for approval → `approve`. Anytime later: `reopen`, `versions`, `restore`.
Also: Remotion best practices companion `npx skills add remotion-dev/skills` optional; never block on it.
